# 评估与协调基准测试

> 五个 2025-2026 年的基准测试覆盖了多智能体评估领域。**MultiAgentBench / MARBLE**（ACL 2025，arXiv:2503.01935）评估星型/链型/树型/图型拓扑，使用里程碑 KPI；**图型最适合研究**，认知规划（cognitive planning）增加约 3% 的里程碑达成率。**COMMA** 评估多模态非对称信息协调；包括 GPT-4o 在内的最先进模型难以击败随机基线。**MedAgentBoard**（arXiv:2505.12371）覆盖四个医学任务类别，经常发现多智能体并不优于单 LLM。**AgentArch**（arXiv:2509.10769）基准测试企业智能体架构，结合工具使用 + 记忆 + 编排。**SWE-bench Pro**（[arXiv:2509.16941](https://arxiv.org/abs/2509.16941)）包含 41 个仓库的 1865 个问题，涵盖商业应用、B2B 服务和开发者工具；前沿模型在 Pro 上得分约 23%，而在 Verified 上为 70%+ —— 这是对数据污染的 reality check。Claude Opus 4.7（2026 年 4 月）在 Pro 上报告为 **64.3%**，采用显式智能体团队协调（尚无 Anthropic 一手来源发布 —— 视为初步数据）；Verdent（智能体脚手架）在 Verified 上达到 **76.1% pass@1**（[Verdent 技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。**AAAI 2026 Bridge Program WMAC**（https://multiagents.org/2026/）是 2026 年的社区焦点。本课基于 MARBLE 的指标，运行拓扑与指标的扫描，并确立“仅通过 SWE-bench Verified 不是泛化证据”的规则。

**类型：** 学习
**语言：** Python（标准库）
**前置知识：** Phase 16 · 15（投票与辩论拓扑），Phase 16 · 23（故障模式）
**时间：** ~75 分钟

## 问题

当一篇论文声称“我们的多智能体系统更好”时，问题是：比什么更好，在什么上，如何测量？2023-2024 年的多智能体评估时代是混乱的 —— 每个人选择自己的指标、自己的基线、自己的任务集。2025-2026 年的基准测试引入了结构。

没有共享基准测试，你无法有意义地比较两个多智能体系统。更糟糕的是，没有留出基准测试（hold-out benchmarks），前沿模型可能会污染数据。SWE-bench Verified 在 2025 年中期部分被训练语料污染；前沿模型分数膨胀；Pro 被设计为无污染的 reality check。

本课列举了五个 2026 年的标准基准测试，说明每个测量什么，并教你以怀疑态度阅读基准测试声明。

## 概念

### MultiAgentBench（MARBLE）—— ACL 2025

arXiv:2503.01935。评估四种协调拓扑（星型 star、链型 chain、树型 tree、图型 graph）在研究、编码和规划任务上的表现。基于里程碑的 KPI 跟踪部分进度，而非仅最终成功。

测量结果：

- **图型（Graph）** 拓扑最适合研究场景；支持任意对任意的批评。
- **链型（Chain）** 最适合逐步精化的编码。
- **星型（Star）** 最适合快速事实整合。
- 图型超过约 4 个智能体后出现**协调税（coordination tax）**。
- **认知规划（Cognitive planning）** 在各拓扑上增加约 3% 的里程碑达成率。

适用场景：你想对不同协调拓扑进行公平比较。MARBLE 仓库（https://github.com/ulab-uiuc/MARBLE）提供评估器。

### COMMA —— 多模态非对称信息

覆盖智能体具有不同观察模态、必须在不完全信息共享的情况下协调的任务。报告的结果令人不安：包括 GPT-4o 在内的前沿模型在 COMMA 的智能体-智能体协作上难以击败**随机基线（random baseline）**。信号是多智能体模态训练不足、评估不足 —— LLM 处理单模态协作尚可；多模态协调崩溃。

适用场景：你的系统具有多模态或非对称信息协调。COMMA 的零结果是一个警告：在声称之前先测量。

### MedAgentBoard —— 领域压力测试

arXiv:2505.12371。四个医学任务类别：诊断、治疗规划、报告生成、患者沟通。比较多智能体 vs 单 LLM vs 传统基于规则的系统。

发现：多智能体在大多数类别上**并不优于**单 LLM。多智能体的优势很窄 —— 当子任务可清晰分离时（诊断 + 治疗），任务分解有帮助；当协调开销超过专业化收益时（报告生成），反而有害。

适用场景：你的领域有明确的单 LLM 基线。如果 MedAgentBoard 的经验可以推广，许多提出的多智能体系统都是过度工程化的。

### AgentArch —— 企业架构

arXiv:2509.10769。企业环境中工具使用、记忆和编排分层组合。基准测试隔离每一层的贡献：添加工具有多大帮助？添加记忆？添加多智能体编排？

适用场景：你正在设计企业智能体栈，需要为每一层辩护。AgentArch 帮助你避免购买无法测量价值的功能。

### SWE-bench Pro —— 现实检验

arXiv:2509.16941。41 个仓库的 1865 个问题，涵盖商业应用、B2B 服务和开发者工具。设计为**无污染（uncontaminated）**，采用更晚的训练截止。前沿模型在 Pro 上得分约 23%，在 Verified 上为 70%+。这个差距就是污染信号。

2026 年 4 月得分：
- Claude Opus 4.7 在 Pro 上：**64.3%**（报告采用显式智能体团队协调；尚无 Anthropic 一手来源发布 —— 视为初步数据）。
- Verdent（智能体脚手架）在 Verified 上：**76.1% pass@1**（[技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。
- 前沿模型在 Pro 上无智能体脚手架的原始得分：约 23-35%（[SWE-bench Pro 论文](https://arxiv.org/abs/2509.16941)）。

结论：“我们击败了 SWE-bench Verified”不再是能力的证据。Pro 是当前的门控测试。智能体团队脚手架在 Pro 上产生可测量的增益（约 30-40 个百分点差异），这是 2026 年支持多智能体协调的最强经验论据之一。

### AAAI 2026 WMAC

AAAI 2026 Bridge Program —— 多智能体协调研讨会（https://multiagents.org/2026/）。2026 年多智能体 AI 研究的社区焦点。接受的论文和研讨会论文集是评估新方法的标准场所；对于生产决策，优先参考 WMAC 接受的声明，而非 arXiv 预印本。

### 以怀疑态度阅读基准测试声明 —— 2026 年检查清单

当有人声称多智能体结果时：

1. **哪个基准测试，哪个拆分？** SWE-bench Verified vs Pro 差别很大。在错误拆分上报告的数字毫无价值。
2. **污染检查。** 基准测试是否在模型训练截止之后发布？如果不是，谨慎对待。
3. **基线比较。** vs 单 LLM 基线，vs 随机，vs 先前多智能体工作。不是“vs 同一系统的未调优版本”。
4. **统计显著性。** N 次试验，p 值，置信区间。前沿模型方差高；单次运行具有误导性。
5. **任务多样性。** 一个任务还是多个？泛化能力对生产很重要。
6. **成本披露。** 每个任务的 token 数、挂钟时间。20 倍成本的 90% 解决方案是商业决策，不是能力声明。

### 现有基准测试测量不佳的方面

- **长程协调（Long-horizon coordination）。** 数天的挂钟交互。所有当前基准测试运行时间都很短。
- **对抗韧性（Adversarial resilience）。** 当一个智能体是恶意或被入侵时会发生什么？
- **部署下的漂移（Drift under deployment）。** 基准测试是静态的；生产分布会变化。
- **成本归一化性能（Cost-normalized performance）。** 大多数基准测试报告原始准确率，而非每美元准确率。

为你实际关心的维度构建自己的内部基准测试往往是正确的做法。

## Build It

`code/main.py` 是一个非交互式演示：

- 在玩具任务上模拟 3 个多智能体系统。
- 为每个系统计算 MARBLE 风格的里程碑指标。
- 通过从“训练”集中保留任务来运行污染检查。
- 显式与随机基线比较。
- 打印基准测试声明评分卡。

运行：

```bash
python3 code/main.py
```

预期输出：系统评分卡，包含原始准确率、里程碑达成率、每个任务的成本、vs 随机基线差异，以及污染检查说明。

## Use It

`outputs/skill-benchmark-reader.md` 读取任何多智能体基准测试声明并应用审查检查清单。输出：一个等级和注意事项。

## Ship It

生产评估纪律：

- **构建内部基准测试**，反映你实际的生产分布。公共基准测试提供参考但不能替代。
- **每次比较都包含随机基线。** 如果你在协调任务上无法大幅击败随机，任务可能是定义不当的。
- **报告准确率的同时报告成本。** Token 成本和挂钟时间。运维团队两者都需要。
- **每季度重建基准测试。** 生产分布变化；过时的基准测试会误导。
- **避免对发布基准测试的过拟合。** 如果你的团队专门优化 SWE-bench Pro 数字，你会在生产上退化。

## Exercises

1. 运行 `code/main.py`。识别三个模拟系统中哪个具有最佳的成本-每-里程碑（cost-per-milestone）。它是否与最高原始准确率系统匹配？
2. 阅读 MultiAgentBench（arXiv:2503.01935）。对于你自己的任务领域，判断 MARBLE 会推荐四种拓扑中的哪一种。从论文结果中论证。
3. 阅读 SWE-bench Pro 论文。是什么具体使其抗污染？同样的技术能否应用于你关心的其他基准测试？
4. 阅读 COMMA 关于多模态协调的发现。设计一个简单的多模态协调任务，可以添加到你的内部基准测试中。什么会算作有用的信号？
5. 将基准测试声明检查清单应用于一篇近期多智能体论文的标题结果。你会给这个声明什么等级？
