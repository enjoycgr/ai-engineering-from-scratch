给定一个工作负载（模型、硬件、目标并发数、面向用户的交互类型 —— 流式聊天 / 一次性 / 语音 / 智能体），生成一个基于 goodput 的 CI/CD SLO 门禁。

产出：

1. SLO 规范。三个阈值：TTFT P99 上限、TPOT P99 上限、端到端 P99 上限。根据交互类型选择合理的值（流式聊天：TTFT 500 ms、TPOT 25 ms、端到端 3 s；语音：TTFT 更紧至 300 ms；智能体：端到端更松至 5 s）。
2. 基准测试方案。工具选择（LLMPerf 或 GenAI-Perf —— 说明你选择的工具及原因）。提示分布（输入和输出 token 的均值 + 标准差）。并发扫描（目标并发数的 25%、50%、100%、150%）。
3. Goodput 计算。公式：同时满足三个约束的请求比例。生产环境目标 >= 99%，金丝雀环境 >= 95%。
4. 百分位数报告。对每个指标报告 P50、P90、P99（绝不只报均值）。均值仅用于合理性检查。
5. 工具陷阱说明。说明该工具在 ITL 中是否包含或排除 TTFT。在跨团队比较前修正定义。
6. 门禁逻辑。CI 通过当且仅当 goodput >= 目标值 且 处于目标并发数。如果 goodput 在 100% 到 150% 并发数之间下降超过 5 个百分点则标红 —— 表明负载测试余量不足。

硬性拒绝：
- 仅基于吞吐量门禁。拒绝并要求 goodput。
- 报告均值而不报 P99。拒绝。
- 省略工具名称和工具版本。拒绝。
- 仅在目标并发数下基准测试；始终进行扫描。

拒绝规则：
- 如果用户没有书面 SLO，拒绝并首先基于交互类型写一份。
- 如果提示分布是"循环中的相同提示"，拒绝 —— 这是提示均匀性陷阱。要求真实合成数据。
- 如果基准测试 < 30 次运行或每次运行 < 100 个请求，因统计量不足而拒绝。

输出：一页 SLO 门禁规范，列出阈值、基准测试方案、工具选择、百分位数报告模板和 CI 通过/失败规则。结尾附一段"接下来测量什么"，根据已知薄弱环节选择 goodput 与并发曲线、提示分布敏感度或 chunked-prefill 开/关尾部对比中的一个。
