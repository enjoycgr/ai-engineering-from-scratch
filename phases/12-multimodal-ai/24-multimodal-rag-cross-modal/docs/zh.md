# 多模态 RAG 与跨模态检索

> 视觉原生文档 RAG 是一个切片。生产多模态 RAG 更宽——跨文本、图像、音频和视频检索，用于旅行规划（"给我找一家安静的纯素早午餐店，有自然光"）、医疗分诊（"什么伤病匹配这张照片 + 这些笔记"）、电子商务（"和我自拍照里类似的穿搭，我的尺码"）和现场服务（"诊断这个引擎声音加零件照片"）。三篇 2025 年综述——Abootorabi 等人、Mei 等人、Zhao 等人——将子问题编纂为：跨模态检索、检索融合、生成定位、多模态评估。本课阅读综述并设计生产流水线。

**类型：** Build
**语言：** Python (stdlib, cross-modal retriever with fusion + grounded generator)
**前置知识：** Phase 12 · 23 (ColPali), Phase 11 (RAG basics)
**时间：** ~180 分钟

## 学习目标

- 设计跨模态检索：文本 → 图像、图像 → 文本、音频 → 视频等。
- 对比三种融合策略：分数融合、基于 attention 的融合、MoE 融合。
- 解释生成定位：当来源是模态混合时"引用你的来源"长什么样。
- 说出 2025 年的三篇经典多模态 RAG 综述及其子问题分类法。

## 问题

单模态 RAG 是解决模式：嵌入查询、嵌入 chunk、检索、塞入 LLM。多模态 RAG 需要：

1. 多个检索头（每模态需要兼容空间中的 embedding）。
2. 跨模态检索结果融合。
3. 跨模态引用来源的生成定位。
4. 覆盖跨模态信号的评估指标。

2025 年综述都到达相同分类法。

## 概念

### 跨模态检索

给定模态 A 的查询检索模态 B 的文档。三种模式：

1. 共享 embedding 空间。CLIP 和 CLAP 在共享空间中产生文本 + 图像 / 文本 + 音频 embedding。跨模态余弦相似度直接工作。限于 CLIP 训练对。

2. 每模态编码器 + 翻译。文本编码器 + 图像编码器 + 空间间映射的小型翻译模块。Gupta 等人的 Sen2Sen 和 2024 年其他设计。灵活但增加复杂度。

3. VLM 作为编码器。使用 VLM 的 hidden state 作为检索表示。VLM 支持的任何模态都工作。更高质量，更昂贵。

选择：文本 + 图像用 CLIP / SigLIP 2；文本 + 音频用 CLAP；前沿质量跨模态用 VLM-hidden-states。

### 融合策略

你检索了 10 个结果：5 张图像、3 段文本、2 个音频片段。如何合并？

分数融合（最便宜）。每模态有自己的检索器，每者返回分数。模态内归一化分数然后求和。简单，通常有效。

基于 attention 的融合。连接所有检索项，让小型 attention 网络加权它们。需要训练。

MoE 融合。Gating 网络路由到模态特定专家。不同查询类型不同路由——视觉问题对图像加权更高。

生产默认：分数融合，对查询主导模态轻微偏置。如果 A/B 显示领域明显获胜，升级到 MoE。

### 生成定位

LLM 应该引用哪个检索项驱动了每个声明。对多模态：

- 文本来源：标准引用 `[1]`。
- 图像来源：`[img 3]` 带简短标题。
- 音频：`[audio 2 at 0:34]`。

用定位感知数据训练生成器：训练目标中每个声明用来源索引标记。推理时，模型自然发出引用。

### 2025 年综述

Abootorabi 等人 (arXiv:2502.08826, "Ask in Any Modality")：多模态 RAG 分类法。覆盖检索、融合、生成。最广泛覆盖。

Mei 等人 (arXiv:2504.08748, "A Survey of Multimodal RAG")：聚焦子任务基准和失败模式。对评估设计有用。

Zhao 等人 (arXiv:2503.18016)：视觉聚焦综述。ColPali 家族工作强。

读全部三个给你 2025 年春最新技术状态。大多数子问题仍然开放。

### MuRAG — 基础论文

MuRAG (Chen 等人, 2022) 是第一个多模态 RAG。从多模态 KB 检索图像 + 文本，生成答案。在 VLM 浪潮前展示可行性。现代系统（REACT、VisRAG、M3DocRAG）在其上构建。

### 生产旅行规划器示例

查询："给我找一家安静的纯素早午餐店，有自然光。"

流水线：

1. 分解查询。"安静" → 音频/评论关键词；"纯素早午餐" → 菜单项；"自然光" → 图像特征。
2. 每模态检索：
   - 文本检索评论："纯素早午餐，安静氛围。"
   - 图像检索餐厅照片："自然光、通风。"
   - 音频检索环境声音片段："低分贝，无音乐。"
3. 融合分数。每家餐厅有复合分数。
4. Top-k 餐厅 → 带所有证据的 VLM 生成器 → 带引用的答案。

这远超文本 RAG。每模态添加文本 alone 错过的信号。

### Agentic 多模态 RAG

多跳：如果首次检索未返回高置信度答案，LLM 重新制定并再次检索。Phase 14 的 Agentic RAG 模式适用。例子：

- 检索初始 top-10 → LLM 要求"太吵，过滤 <40 dB" → 重新检索。
- 检索图像 → LLM 看到一张有菜单 → 检索菜单文本 → 答案。

增加复杂度但处理单次检索无法处理的查询。

### 评估

跨模态评估仍不成熟。常见代理：

- 每模态 Recall@k。
- 融合 top-k 准确率。
- 人类评判端到端满意度。
- 任务特定（完成的预订、购买的商品）。

无标准基准跨越所有模态。大多数论文在领域特定任务上评估。

## 使用它

`code/main.py`：

- 三个 mock 检索器（文本、图像、音频）在共享餐厅语料库上运行。
- 带可配置权重的分数融合，组合模态分数。
- 发出带引用的最终答案的生成器 stub。
- 置信度低时重新制定查询的简单 agentic 循环。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| Cross-modal retrieval | "Query one modality, retrieve another" | 文本查询检索图像；图像查询检索文本；需要共享空间或翻译器 |
| Score fusion | "Combine scores" | 每模态检索分数的加权和；最简单融合 |
| MoE fusion | "Modality-routed experts" | Gating 网络挑选每查询信任哪个模态的分数 |
| Grounded generation | "Cite your sources" | 答案中每个声明用来源索引标记 |
| MuRAG | "First multimodal RAG" | 2022 年建立多模态 RAG 模式的论文 |
| Agentic multi-hop | "Reformulate and retry" | 首次通过置信度低时 LLM 重新查询检索器 |
