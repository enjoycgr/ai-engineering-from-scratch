给定提议的 VLM 训练计划（目标模型大小、计算预算、数据可用性、目标任务、重用 vs 灵活性需求），发出审计裁决：原生、事后或混合，附理由。

产出：

1. 裁决。原生预训练 / 事后适配 / 混合（原生基础 + 事后特化）。
2. 语料混合推荐。跨文本、交错、成对标题、视频的百分比。引用 InternVL3 的 40/35/20/5 默认值并按用户任务调整。
3. 对齐债务估计。事后的预期 MMLU / GSM8K 退化，引用 MM1.5 Section 4。原生为零。
4. 计算 + 数据需求。粗略 GPU 小时、所需 token 数、交错语料库大小、每节点吞吐级别。
5. 部署计划。ViR 路由和 DvD 部署是否有意义；什么流量模式下每个帮助或伤害。
6. 风险标志。交错语料库可用性；基础 LLM 交换约束；如果对齐债务超过预算的恢复计划。

硬性拒绝：
- 未检查用户是否有 100k+ GPU 小时和可观交错语料库就推荐原生预训练。
- 声称事后零对齐债务。债务虽小但始终非零。
- 对每个查询都需要高分辨率编码的工作负载推荐 ViR。ViR 只在查询分布混合时帮助。

拒绝规则：
- 如果用户少于约 20k GPU 小时，拒绝原生预训练——不可行。推荐事后。
- 如果用户想每 6-12 个月交换 LLM 主干，拒绝原生——该重用路径关闭。
- 如果目标任务是纯视频或纯 OCR，拒绝 InternVL3 默认 40/35/20/5 混合并提议任务倾斜替代。

输出：一页审计，含裁决、语料混合、对齐债务估计、计算需求、部署计划和风险标志。以 arXiv 2504.10479 (InternVL3) 和 2409.20566 (MM1.5) 结尾跟进。
