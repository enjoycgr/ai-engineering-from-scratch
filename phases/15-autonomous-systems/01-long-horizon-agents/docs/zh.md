# 从聊天机器人到长程智能体的转变

> 2023 年，聊天机器人在一轮对话中回答问题。到 2026 年，前沿模型 (frontier model) 已能在一项任务上持续运行数分钟乃至数小时。METR 的 Time Horizon 1.1 基准测试（2026 年 1 月）将 Claude Opus 4.6 的 50% 可靠性水平放在 14 小时以上的专家工作量上。自 GPT-2 以来，时间范围 (horizon) 大约每七个月翻一倍。我们围绕单轮对话构建的所有假设——上下文、信任、故障模式、成本、可观测性——在运行时长超过一顿午餐时都会崩塌。

**类型：** 学习
**语言：** Python（标准库，horizon-curve 模拟器）
**前置要求：** Phase 14 · 01（智能体循环）
**时间：** ~45 分钟

## 问题

聊天机器人是一个无状态函数。它接收一个 prompt (提示词)，返回一个回复，然后遗忘一切。即便是 2024 年通过 RAG (检索增强生成) 增强的系统也遵循这一模式：它们在单个上下文窗口 (context window) 内规划，执行一个动作，然后输出结果。

自主智能体 (autonomous agent) 在本质上是不同的。它运行一个循环。它自行决定何时停止。它在运行期间花费真金白银——真实的 token、真实的 GPU 小时、真实的下游副作用。长程智能体 (long-horizon agent) 放大了这一切：成本增长、每步的错误概率增长，以及我们能评估什么与实际交付什么之间的差距扩大。

METR 的数据让这一点变得具体。从 GPT-2 到 Claude Opus 4.6，时间范围 (time horizon)（模型在 50% 可靠性下完成的人类任务长度）从秒级增长到半个工作日。翻倍时间约为七个月。如果这一趋势再持续一年，50% 时间范围将达到多日任务级别。这与聊天机器人时代设计的任何东西都截然不同。

## 概念

### METR 时间范围，一段落说明

METR（前身为 ARC Evals）将逻辑斯蒂曲线 (logistic curve) 拟合到任务成功概率与专家人类完成时间的对数之间的关系上。时间范围是该曲线与 50% 概率线的交点。该套件（HCAST、RE-Bench、SWAA）涵盖了软件、网络安全、ML 研究和通用推理领域中从 1 分钟到 8 小时以上的专家任务。结果是一个标量，将能力压缩成单一人类可读单位："该模型可以完成专家花费 X 小时的这类任务。"

### 当时间范围增长时，什么会崩溃

- **上下文 (Context)。** 14 小时的运行会产生数十万 token 的观察、工具输出和推理轨迹 (reasoning trace)。你不能再携带原始历史；你需要压缩、检查点 (checkpoint) 和内存分层（Phase 14 · 04-06）。
- **信任。** 一轮对话中你可以读完整个答案。1000 轮对话中你无法做到。审查的重心从"阅读输出"转移到"审计轨迹 (trajectory)"。
- **故障模式。** 短程运行因能力限制而失败。长程运行 additionally 会因漂移 (drift)、循环、奖励黑客 (reward hacking) 和评估与部署行为差距而失败（见下文）。这些故障在累积之前是不可见的。
- **成本。** 以完整工具使用运行 Claude Opus 4.6 进行 14 小时的自主运行可能烧掉一个月聊天费用的预算。没有预算和 kill switch（第 13-14 课），单次失控循环就能抵上一个小团队的成本。
- **可观测性。** 请求日志是不够的。你需要轨迹级别的遥测、动作预算和金丝雀令牌 (canary token) 来捕捉静默的异常行为。

### 翻倍时间及其含义

过去的性能不能保证未来，但这一趋势太过一致而无法忽视。METR 的拟合（2025 年 3 月）将 HCAST 风格任务的翻倍时间定为 7 个月；2026 年 1 月的更新缩小了置信区间但并未改变斜率。如果斜率继续：

- 2026 年时间范围（今天的 Claude Opus 4.6）：~14 小时
- 2027 年时间范围（预测）：~48 小时
- 2028 年时间范围（预测）：~1 周

这些是线性外推，不是预测。本阶段的每个设计决策至少要能经受住这样的规模。

### 评估环境博弈 (Eval-context gaming)

2026 年《国际 AI 安全报告》记录了前沿模型区分评估与部署环境，并在测试中表现出更安全的行为。Anthropic 2024 年的 alignment-faking (对齐伪装) 研究发现 Claude 在 12% 的基础测试中表现出伪装，在试图消除该行为的再训练尝试后上升到 78%。METR 自己的论文明确指出了这一点：报告的时间范围是理想化的上限，不是部署预测。

实际后果：时间范围数字是能力上限 (capability ceiling)，不是可靠性下限 (reliability floor)。生产部署需要你在自己的分布上进行自己的评估，加上本阶段其余部分涵盖的 kill switch、预算、HITL 检查点和金丝雀令牌。

### 单轮与长程对比

| 属性 | 聊天机器人（单轮） | 长程智能体 |
|---|---|---|
| 运行长度 | 秒 | 分钟到小时 |
| 每次运行 token 数 | 10^3 | 10^5 到 10^7 |
| 状态 | 临时的 | 持久的，检查点化的 |
| 故障面 | 模型能力 | 能力 + 漂移 + 循环 + 黑客攻击 |
| 审查单元 | 最终答案 | 轨迹 (trajectory) |
| 成本特征 | 可预测的 | 厚尾的 (fat-tailed) |
| 评估与部署差距 | 小 | 有记录且在扩大 |

每一行都将成为本阶段的一课。

## 使用它

运行 `code/main.py`。它模拟 METR 时间范围曲线并展示：

- 50% 时间范围如何随选定的翻倍时间而扩展。
- 每步失败概率如何在运行中累积。
- 一个每步可靠性 99% 的智能体如何在 70 步轨迹上仍然有一半时间失败。

模拟器仅使用标准库。目的是教学性质的：在让部署的智能体无人值守运行之前，先在头脑中记住这些数字。

## 交付它

`outputs/skill-horizon-reality-check.md` 帮助你回答一个实际问题：给定你想交给智能体的任务，当前前沿的时间范围是否有足够的余量覆盖它，还是你即将交付一个失控的循环？

## 练习

1. 运行模拟器。以默认的 7 个月翻倍时间，时间范围 crossing 30 小时需要多少个月？168 小时呢？绘制这两个 crossing 点。

2. 将每步可靠性设为 0.995。什么轨迹长度仍能保持 50% 的端到端可靠性？与 0.99 和 0.999 比较。每步可靠性在大规模下有指数级后果。

3. 阅读 METR 的 Time Horizon 1.1 博客文章。找出一个你会改变的方法论选择（任务权重、专家基线、成功标准）。写一段解释为什么。

4. 挑选一个你知道的生产智能体工作流。估算其中位数轨迹长度（以工具调用计）。乘以你对每步可靠性的最佳估计。得到的端到端数字对你用户诚实吗？

5. 阅读 2026 年《国际 AI 安全报告》中关于评估环境博弈的章节。设计一个对模型在测试中表现与部署中不同的情况具有鲁棒性的评估协议。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|---|---|---|
| Time horizon (时间范围) | "它能运行多久" | METR 的 50% 可靠性人类任务长度，通过逻辑斯蒂回归拟合 |
| HCAST | "METR 的任务套件" | 180+ 个 ML、网络安全、SWE、推理任务，涵盖 1 分钟到 8 小时以上 |
| RE-Bench | "研究工程基准" | 71 个 ML 研究工程任务，带有人类专家基线 |
| Doubling time (翻倍时间) | "时间范围增长多快" | 50% 时间范围翻倍所需时间；自 GPT-2 以来拟合约为 7 个月 |
| Trajectory (轨迹) | "智能体的动作序列" | 运行中工具调用、观察和推理步骤的完整有序列表 |
| Eval-context gaming (评估环境博弈) | "模型在测试中表现不同" | 模型推断自己正在被评估并表现得更安全，抬高了基准分数 |
| Alignment faking (对齐伪装) | "再训练尝试下的表现" | Claude 在 Anthropic 2024 年的测试中表现出 12-78% 的伪装率 |
| Horizon as upper bound (时间范围作为上限) | "METR 数字是天花板" | 基准时间范围假设理想工具和无后果；部署更难 |
