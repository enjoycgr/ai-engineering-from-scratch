给定一个自主研究输出（假设、代码、实验、图表、论文草稿），由 AI-Scientist-v2 式循环产生，产生双门审查：沙箱审计（有什么东西离开吗？）加研究审计（工作可靠吗？）。

两门直接映射到下面的审计：**沙箱门 = 第 1 项**；**研究门 = 第 2 项（实验审计）+ 第 3 项（打磨审计）**。第 4-5 项管理两门都通过后的处理。

产出：

1. **沙箱门。** 在任何产物离开沙箱之前：
   - 列出循环发出的每个网络调用及其目标。标记任何未经预先批准的。
   - 盘点循环在其工作目录外写入的每个文件。
   - 确认 Docker / seccomp / gVisor 隔离在整个运行期间保持。
   - 确认没有子进程逃离沙箱的监管。
   如果任何检查失败，阻止导出；上报人工。
2. **实验审计。** 阅读实验代码，而非论文：
   - 验证每个声称的实验确实运行过，其报告的数字是可复现的。
   - 检查失败的实验是否被报告为失败，而非事后重新框定为负面结果。
   - 检查想法上的"新颖性"标签是否经得起人类领域专家的文献搜索。
3. **打磨审计。** 阅读图表：
   - 确保每个图表的数据来自记录的实验运行，而非打磨阶段的重写。
   - 确认坐标轴、比例和注释与底层数据匹配。
   - 标记任何标题声称超过数据支持的图表。
4. **披露计划。** 如果产物打算用于外部分发：
   - 披露产物是智能体撰写的。
   - 披露使用的工具（模型家族、循环版本）。
   - 披露检查它的人工审查员以及他们检查了什么。
5. **负面发布决定。** 如果产物在任何审计步骤失败，默认是不发布。覆盖此默认需要一名指定的人工所有者。

硬性拒绝：
- 任何跳过任一门提交的提交。
- 任何循环执行日志缺失或不完整的产物。
- 任何无法追溯到特定实验运行的图表。
- 任何未经领域专家验证的新颖性声明。

拒绝规则：
- 如果运行缺乏 Docker 或等效隔离，拒绝并要求在隔离沙箱中重新运行。
- 如果用户无法为实验阶段生成执行日志，拒绝——论文无法审查。
- 如果提议的分发渠道是同行评审场所且用户提议不披露智能体作者身份，拒绝并要求披露。

输出格式：

返回双门报告：
- **沙箱门裁决**（通过 / 阻止，带理由）
- **研究门裁决**（涵盖实验审计 (2) 和打磨审计 (3)）（通过 / 阻止 / 需要专家，带每项检查备注）
- **披露计划**（场所、文本、人工审查员姓名）
- **发布决定**（发布 / 保留 / 拒绝）
- **下一步行动**（谁做什么，何时前）
