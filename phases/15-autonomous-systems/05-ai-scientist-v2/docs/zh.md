# AI Scientist v2 — 研讨会级别的自主研究

> Sakana 的 AI Scientist v2（Yamada 等人，arXiv:2504.08066）运行完整的研究循环：假设、代码、实验、图表、撰写、提交。它是首个有生成论文通过 ICLR 2025 研讨会同行评审的系统。独立评估（Beel 等人）发现 42% 的实验因编码错误失败，文献综述经常将成熟概念误标为新概念。Sakana 自己的文档警告代码库执行 LLM 编写的代码并推荐 Docker 隔离。这幅图景的两半都是重点。

**类型：** 学习
**语言：** Python（标准库，研究循环状态机玩具）
**前置要求：** Phase 15 · 03（AlphaEvolve），Phase 15 · 04（DGM）
**时间：** ~60 分钟

## 问题

研究是一个开放式任务。与 AlphaEvolve 的算法搜索或 DGM 的基准约束自我修改不同，研究结果没有机器可检查的正确性标准。论文由评审员评判，而非单元测试。这使循环更难闭合——但如果闭合了也更有价值，因为研究是复合进步的所在。

AI Scientist v1（Sakana，2024）通过从人类编写的模板开始来闭合循环。LLM 在固定脚手架内填充实验。AI Scientist v2（Yamada 等人，2025）通过使用带视觉语言模型 (vision-language model, VLM) 批评循环的智能体树搜索移除了模板要求。系统生成想法、实现实验、制作图表、撰写论文，并在评审员反馈上迭代。

同行评审裁决：一篇 v2 生成的论文被 ICLR 2025 研讨会接受（已披露）。独立评估裁决：系统远非可靠。两者都是真的。

## 概念

### 架构

1. **想法生成。** LLM 提出以主题和先前文献为条件的研究想法。v1 使用模板；v2 使用假设空间的智能体搜索。
2. **新颖性检查。** 文献检索步骤检查该想法是否已发表。这是 Beel 等人的评估发现误标的步骤——成熟方法经常被归类为新概念。
3. **实验计划。** 智能体起草实验协议并编写代码。
4. **执行。** 代码在沙箱中运行。失败被反馈到重试循环中。在 Beel 等人的测量中，42% 的实验因编码错误在此阶段失败。
5. **图表生成。** 视觉语言模型读取生成的图表并重写以提高清晰度。这是 v2 的关键技术补充。
6. **撰写。** LLM 起草论文，与内部评审员迭代。
7. **可选：提交。** 论文提交到会议。

### 研讨会接受结果意味着什么

一篇 v2 生成的论文通过了 ICLR 2025 研讨会的同行评审。作者向程序委员会披露了论文的来源。接受是一个数据点；它不是声称系统"做研究"的许可证。

重要背景：研讨会论文的门槛低于主会论文。同行评审是有噪声的；任何给定日子都有小部分提交被接受。一次成功是概念验证，不是可靠性声明。Nature 2026 论文记录了端到端循环，本身由人类研究人员共同撰写；它不是"系统写了一篇 Nature 论文"。

### 独立评估发现了什么

Beel 等人（arXiv:2502.14297）进行了外部评估。主要发现：

- **实验失败。** 42% 的实验因编码错误失败（错误的导入、维度不匹配、未定义变量）。重试循环捕获了一些，不是所有。
- **新颖性误标。** 文献检索步骤经常将成熟概念标记为新概念。这是研究领域的幻觉等价物。
- **展示质量差距。** 视觉语言图表批评产生了出版级视觉效果，掩盖了潜在的实验弱点。

最后一个发现对本阶段最重要。一个产生有说服力输出但没有做有说服力研究的系统，比一个明显失败的系统更危险，而非更安全。评估必须触及底层主张，而非止步于图表。

### 沙箱逃逸 (sandbox escape) 担忧

Sakana 自己的仓库 README 警告：

> 由于该软件执行 LLM 生成代码的性质，我们无法保证安全。存在危险包、不受控制的网络访问和产生非预期进程的风险。使用风险自负，并考虑 Docker 隔离。

这是未验证领域中自主性的操作形态。LLM 编写代码；代码运行；代码可以做进程被允许做的任何事。没有硬限制文件系统、网络和进程动作的沙箱，任何自主研究智能体都可以外泄数据、燃烧计算资源或重写自身。

AlphaEvolve 的沙箱故事更容易，因为它的评估器是紧的。AI Scientist v2 的循环运行开放式代码和开放式目标。这就是为什么它需要更强的隔离（最低 Docker；seccomp / gVisor 首选）和在论文离开系统前进行人工审查。

### v2 在前沿技术栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知故障 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元测试 + 基准 | 受评估器严谨性约束 |
| DGM | 智能体脚手架 | 代码 | SWE-bench | 奖励黑客 |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（弱） | 实验失败、误标、打磨掩盖弱点 |

v2 拥有三者中最弱的自动评估器、最宽的输出面和通往公共产物的最短路径。操作控制（沙箱、审查、披露）承担了大部分安全工作。

## 使用它

`code/main.py` 将 v2 循环模拟为状态机：想法 → 新颖性检查 → 实验 → 图表 → 撰写 → 评审 → 接受或迭代。每个状态都有从 Beel 等人发现中提取的可配置失败概率。运行 N 次循环并计数：

- 多少想法到达提交。
- 多少提交会有精美论文掩盖的关键实验缺陷。
- 重试预算如何权衡质量与产出。

## 交付它

`outputs/skill-ai-scientist-sandbox-review.md` 是研究循环智能体产生的任何东西在离开沙箱之前的双门审查清单。

## 练习

1. 使用默认参数运行 `code/main.py`。多大比例的循环运行产生"干净"的论文？多大比例产生有实验失败缺陷但图表批评打磨掉的论文？

2. 默认值已经使用 Beel 等人的 42% / 25%。用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 重新运行，然后用 `--experiment-failure 0.60 --novelty-mislabel 0.40` 重新运行。两次运行之间，精美但有缺陷的份额如何变化？

3. 阅读 Sakana 的 AI Scientist v2 仓库 README 关于沙箱要求的内容。为多日自主运行命名两个你会应用的额外限制（超越 Docker）。

4. 阅读 Beel 等人第 4 节关于展示质量差距的内容。设计一个能捕捉看起来精美但实验有缺陷的论文的额外评估器。

5. 为研究智能体输出提议一个比"博士生阅读每篇论文"更具可扩展性的人工审查协议。识别瓶颈并围绕它设计。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|---|---|---|
| AI Scientist v1 | "Sakana 的模板化研究智能体" | 将实验填充到固定脚手架中 |
| AI Scientist v2 | "无模板研究智能体" | 带 VLM 图表批评的智能体树搜索 |
| Agentic tree search (智能体树搜索) | "分支研究智能体" | 并行展开多个实验计划；通过内部批评剪枝 |
| Vision-language critique (视觉语言批评) | "VLM 打磨图表" | 多模态模型读取图表并重写以提高清晰度 |
| Literature retrieval (文献检索) | "新颖性检查" | 搜索先前工作以确认想法新颖性——有记录的误标 |
| Polish masking (打磨掩盖) | "漂亮论文，破碎研究" | 展示质量超过实验质量；掩盖弱点 |
| Sandbox escape (沙箱逃逸) | "LLM 代码突破" | 智能体执行的代码做了循环设计者未预期的事 |
