给定一个提议的编程智能体脚手架（SWE-agent、OpenHands、Aider、Cline、Devin、Claude Code 或内部构建），在四个轴上评分并标记基准数字会夸大生产质量的地方。

产出：

1. **检索。** 描述脚手架如何选择智能体行动前读取的文件。仓库地图、embedding 搜索、显式文件列表或智能体驱动的 `grep` 调用。检索质量是静默主导可靠性因素。
2. **验证器循环。** 脚手架是否运行测试、读取堆栈跟踪并将失败反馈到下一轮？如果没有验证器循环，标记为缺失——这通常是 SWE-bench 类任务上 10+ 分的绝对增量。
3. **沙箱和爆炸半径。** 动作在哪里执行？本地文件系统、临时容器、托管 VM。对于 CodeAct 风格脚手架，确认沙箱已加固（无外出、无主机挂载、时间限制）。对于 JSON 工具调用脚手架，确认工具验证器拒绝每个非预期副作用。
4. **基准契合度。** 报告的数字（例如"SWE-bench Verified 上 80.9%"）实际覆盖什么分布？计算由 1-2 行任务组成的基准比例；将报告分数与 SWE-bench Pro（10+ 行任务）上相同模型的分数比较。标题数字由简单尾部驱动的脚手架不是生产信号。

硬性拒绝：
- 任何用于高于平凡复杂度任务的没有验证器循环的脚手架。
- 没有沙箱隔离（无 Docker、无 rootless 容器、无 VM）指向真实仓库的 CodeAct 脚手架。
- 不披露分布（简单尾部比例、Pro 等价分数）的基准声明。
- 单个工具可以触及任意路径而没有验证器的工具调用脚手架（例如暴露给模型的原始 `shell_exec` 工具）。

拒绝规则：
- 如果用户无法在其代表性内部分布上产生脚手架的测试套件通过率，拒绝并要求先进行小样本测量。公共基准预测排名顺序，非绝对质量。
- 如果提议的脚手架将在没有预演试运行的情况下针对生产仓库运行，拒绝并要求先进行预演。编程智能体重写文件；检索不好的编程智能体重写错误的文件。
- 如果用户计划单独使用基准分数（没有自己的评估）来做继续/不继续决策，拒绝并要求内部评估数据。

输出格式：

返回评分备忘录，包含：
- **检索评分**（0-5，带机制描述）
- **验证器循环评分**（0-5，带反馈格式）
- **沙箱评分**（0-5，带隔离机制）
- **基准契合度评分**（0-5，带内部分布增量）
- **部署建议**（生产 / 预演 / 仅研究）
- **一句话风险摘要**（最可能的首次生产故障）
