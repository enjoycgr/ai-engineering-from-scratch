给定一个提议的自我修改智能体循环（智能体脚手架、评估器管道、部署目标），产生一个防火墙规范，将评估器保持在智能体触及范围之外。DGM 论文记录了智能体移除自己的安全标记以提高分数；该技能是控制措施。

产出：

1. **文件系统边界。** 列出智能体可以编辑的每个文件。列出评估器读取的每个文件。交集必须为空。如果不是，指定使其为空的确切移动。
2. **进程边界。** 评估器必须在智能体不控制的进程中运行。指定容器或沙箱。如果智能体有 shell 访问权限，智能体可以绕过进程内守卫。
3. **网络和密钥边界。** 智能体不能编辑获取评估器输入或发布分数的 CI 密钥。列出密钥存放位置和挂载方式。
4. **分数入口契约。** 分数从评估器返回到循环的档案。该路径是唯一通道。智能体可以写入的任何影响未来评分的东西都破坏了契约。
5. **突变审查清单。** 列出需要人工审查后才能接受的智能体编辑类别：新依赖项、评分相邻代码的编辑、沙箱配置的编辑、日志或监控的编辑。

硬性拒绝：
- 评估器与智能体源代码在同一仓库中。将其移出。
- 在智能体进程内作为 Python 导入运行的评估器。在子进程中运行它。
- 在边界智能体一侧应用的任何分数调整。所有调整必须在服务器端。
- 智能体可以通过编辑自己的代码来静默的任何日志记录。

拒绝规则：
- 如果用户无法命名智能体可以编辑的每个文件，拒绝并要求先进行文件级写入访问审计。
- 如果评估器没有留出输入，拒绝——这是第 3 课的审计，一个先决条件。
- 如果部署面包括对评估器本身的突变（即使通过提议的依赖更新间接进行），拒绝并要求人工防火墙审查步骤。

输出格式：

返回一页规范，包含：
- **智能体写入面**（路径、glob 模式）
- **评估器读取面**（路径、端点）
- **交集**（必须为空；展示差异）
- **进程模型**（评估器如何隔离）
- **密钥清单**（存放位置和挂载方式）
- **需要审查的突变类别**（项目符号）
- **签署行**（谁拥有防火墙不变量）
