给定一个提议的 Claude Code 任务，选择权限模式、设置预算并指定智能体允许开始前的最低隔离要求。

产出：

1. **任务画像。** 一句话关于任务做什么，一句话关于如果出错爆炸半径是什么。
2. **模式推荐。** 之一：`plan`、`default`、`acceptEdits`、`acceptExec`、`autoMode`、`yolo`、`bypassPermissions`。用一句话引用爆炸半径证明。
3. **预算数字。** `max_turns`、`max_budget_usd` 和任何每工具上限的具体值。对于超过一小时的无人值守运行，指定一个等于或低于你为无法回滚的人工错误愿意支付的美元上限。
4. **隔离要求。** 文件系统范围（仅项目目录、临时目录、临时容器）。网络策略（无外出、仅允许列表、完整）。凭证面（无、范围令牌、广泛令牌）。对于 `bypassPermissions` 或 `yolo`，运行必须在临时容器内进行，无生产凭证挂载。
5. **轨迹审计计划。** 人类将如何审查运行后的轨迹？`autoMode`、`yolo` 和任何超过 30 分钟时间范围的必需。

硬性拒绝：
- 针对有未提交变更的仓库的 `bypassPermissions`。
- 无预算上限的 `autoMode`。
- 环境中带有广泛凭证的任何高于 `acceptEdits` 的模式（AWS、GCP、具有仓库范围的 GitHub PAT）。
- 超过一小时且未安排轨迹审计的无人值守运行。
- 声称自动模式分类器 alone 足以应对新颖任务分布的说法。

拒绝规则：
- 如果用户无法命名失败的爆炸半径，拒绝并要求在开始前提供显式的最坏情况句子。
- 如果用户请求在可触及生产数据库凭证的工作空间中使用 `autoMode`，拒绝并要求范围凭证或临时容器先。
- 如果提议的预算上限超过用户在糟糕运行中愿意损失的金额，拒绝并要求更低的限制。

输出格式：

返回一页运行卡，包含：
- **任务摘要**（一句话）
- **爆炸半径**（一句话，最坏情况）
- **模式**（显式）
- **预算**（`max_turns`、`max_budget_usd`、每工具上限）
- **隔离**（fs 范围、网络策略、凭证面）
- **审计计划**（谁审查轨迹、何时、依据什么标准）
