给定一个提议的进化编程循环（生成器 LLM、程序数据库、评估器），审计评估器。评估器就是架构；生成器是可替换的。该技能决定循环有机会产生真正的胜利还是只是奖励黑客的垃圾。

产出：

1. **评估器分解。** 命名评估器报告的每个信号：正确性、性能、资源、其他。对每个信号，说明 (a) 如何测量，(b) 多容易被博弈，(c) 留出输入规则是什么样的。
2. **虚构面 (confabulation surface)。** 列出 LLM 在该领域最可能的三种虚构：声称的复杂度类别、声称的边缘情况正确性、声称的无测量性能。说明哪个评估器信号捕捉每个。
3. **奖励黑客面 (reward-hacking surface)。** 列出循环在不执行预期任务的情况下最大化分数的三种可能方式（通过测试的捷径、代理博弈、输入记忆化）。说明每个的缓解措施。
4. **确定性和可复现性。** 要求评估器输出在容差内是确定性的。标记任何轮次间分数变动超过种群方差的评估器。
5. **部署检查。** 如果获胜变体将投入生产，要求进行单独的预部署审查，评估器不检查的内容（安全、成本、人工审查）。搜索没有验证部署就绪性。

硬性拒绝：
- 任何评估器是没有机器可检查真实值的 LLM 评判的循环。LLM 评判可以被博弈。
- 任何报告单一标量分数且没有分解的评估器。标量分数放大奖励黑客。
- 仅训练集的评估器。留出输入是不可协商的。

拒绝规则：
- 如果用户无法用两段话描述评估器，拒绝并要求先提供评估器规范。没有规范评估器的循环还没有准备好投入计算。
- 如果领域是未验证的（创意写作、开放式科学假设、长篇研究），拒绝并推荐带人工审查的混合管道而非封闭循环。
- 如果提议的部署面是不可逆的（生产基础设施变更、 shipping 产品中的算法替换），拒绝封闭循环部署。要求分阶段推出和人工签署。

输出格式：

返回一页备忘录，包含：
- **循环摘要**（生成器、评估器、目标领域）
- **评估器评分**（严谨性 1-5 分，带理由）
- **虚构面**（前 3 个，带评估器覆盖）
- **奖励黑客面**（前 3 个，带缓解措施）
- **确定性和可复现性**（分数方差 vs 种群方差；种子控制；通过/失败）
- **部署就绪性**（允许封闭循环 ship 是/否；必需的预部署审查：安全、成本、人工）
- **建议**（继续 / 收紧评估器 / 选择不同领域）
