给定一个拟议的浏览器智能体工作流，生成一份信任边界界定文档，枚举每一次读取、每一次写入，以及首次运行所需的最低防御栈。

产出：

1. **读取面。** 列出智能体将请求的每个 origin。将每个分类为 in-trust（用户组织运营的第一方站点）或 out-of-trust（任何第三方、任何用户生成内容、任何搜索结果）。所有 out-of-trust 读取必须被视为潜在的提示注入通道。
2. **写入面。** 列出智能体被授权采取的每个 consequential 行动（提交表单、发布内容、调用后端工具、写入记忆）。对每个行动，说明爆炸半径以及该行动是否可逆。
3. **所需防御。** 最低栈：内容消毒器、读写边界（当 content_origin 为 out-of-trust 时写入需要新批准）、每任务工具白名单、带限定凭证的会话隔离、持久记忆上的金丝雀令牌、不可逆行动上的人类介入。
4. **基准到分布的契合度。** 如果智能体报告了 BrowseComp、OSWorld 或 WebArena-Verified 分数，说明基准测试与真实任务之间的分布重叠度。高 BrowseComp 分数并不能预测预订流程的可靠性。
5. **已知攻击检查清单。** 确认部署已加固防御 (a) 可见文本注入，(b) URL 片段 / 查询注入，(c) 记忆绑定攻击（Tainted Memories 类），(d) 认证会话上的类 CSRF 攻击，(e) 一键劫持。对每个攻击，命名具体防御措施及其生效位置。

硬性拒绝：
- 可访问生产凭证且无会话隔离的浏览器智能体。
- 任何由 out-of-trust 内容发起的写入不需要新 HITL 批准的部署。
- 仅依赖内容消毒器的部署（消毒器捕获简单攻击；复杂载荷仍可穿透）。
- 无金丝雀条目的持久记忆。
- 触及金融交易或客户数据且无写入 HITL 的工作流。

拒绝规则：
- 如果用户无法命名注入驱动错误写入的爆炸半径，拒绝并要求在开始前提供显式句子。
- 如果用户提议在一个限定凭证不可用的堆栈上运行浏览器智能体，拒绝并要求先建立独立身份。
- 如果用户引用基准分数（BrowseComp、OSWorld、WebArena）作为智能体"能"完成生产任务的证据，拒绝并要求在真实分布上进行内部评估。

输出格式：

返回一份信任边界备忘录，包含：
- **读取面表**（origin，in-trust / out-of-trust）
- **写入面表**（行动，爆炸半径，可逆 y/n）
- **防御栈**（已配置层的项目符号列表）
- **基准契合度说明**（如适用）
- **已知攻击检查清单**（五行，每行命名防御）
- **部署裁决**（production / staging / research-only）
