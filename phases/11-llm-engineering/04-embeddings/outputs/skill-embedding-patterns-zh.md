# Embedding Patterns（嵌入模式）

每个 embedding 工作流都遵循以下契约：

```
text -> embed(text) -> vector (float array)
similarity(vector_a, vector_b) -> score (float)
```

Embedding 模型和相似度度量是唯一两个重要的决策。其他都是管道工程。

## 何时使用 embedding

- 跨文档的语义搜索（查找含义，而非关键词）
- 聚类相似项目（支持工单、产品评论、错误报告）
- 通过最近邻进行分类（通过与标注示例的相似度来标记新项目）
- 推荐系统（查找与用户喜欢的项目相似的项目）
- 去重（使用相似度阈值查找近似重复内容）

## 何时不使用 embedding

- 精确关键词匹配（使用全文搜索）
- 结构化查询（使用 SQL、过滤器）
- 小数据集，手动标注更快（<100 个项目）
- 可解释性比准确性更重要的任务（embedding 是不透明的）

## 模型选择

根据你的约束条件进行选择：

- **需要 API，最佳性价比**：OpenAI text-embedding-3-small（1536d，$0.02/1M tokens）
- **需要最高准确率**：Voyage-3（1024d，$0.06/1M tokens，最高 MTEB）
- **需要本地/私有**：BGE-M3（1024d，免费，多语言，推荐 GPU）
- **需要快速本地原型设计**：all-MiniLM-L6-v2（384d，免费，可在 CPU 上运行）
- **需要多语言**：Cohere embed-v3（1024d）或 BGE-M3（两者多语言表现均强）

规则：切勿在索引和查询之间混用不同的 embedding 模型。不同模型的向量位于不兼容的空间中。

## 分块规则

1. 目标每块 256-512 个 token，50 个 token 重叠
2. 尽可能避免在句子中间分割
3. 为每个块包含元数据（源文件、章节标题、位置）
4. 对于结构化文档（Markdown、HTML），首先在标题边界处分割
5. 通过搜索已知答案并检查检索结果来测试分块质量

## 相似度度量选择

- **余弦相似度（Cosine similarity）**：默认选择，处理可变长度文本，已归一化
- **点积（Dot product）**：当向量已经单位归一化时使用（OpenAI 模型已归一化），计算稍快
- **欧几里得距离（Euclidean distance）**：用于聚类，当绝对位置重要时

当向量已归一化时，这三种度量给出相同的排名。选择仅在向量未归一化时才重要。

## 存储优化

三个可叠加的压缩级别：

1. **Matryoshka 截断**：减少维度（1536 -> 256 = 节省 6 倍，准确率损失 3-5%）
2. **Float16 量化**：每个维度的存储减半（节省 2 倍，准确率损失 <1%）
3. **二值量化**：每个维度 1 位（节省 32 倍，准确率损失 5-10%，需配合重排序使用）

生产模式：对完整语料库进行二值搜索，使用 float32 向量对前 1000 个结果重新评分。

## 检索-然后-重排序（Retrieve-then-rerank）

两阶段流水线以获得最佳准确率：

1. 双编码器（Bi-encoder）检索前 100 个候选（快速，使用预计算 embedding）
2. 交叉编码器（Cross-encoder）重排序至前 10 个（慢速，处理每个查询-文档对）

这在精确度指标上比单阶段检索高出 10-15%。当准确率比延迟更重要时使用。

## 常见错误

- 对索引和查询使用不同的 embedding 模型
- 嵌入整个文档而不是分块（embedding 变成所有内容的平均值）
- 在计算余弦相似度之前不归一化向量（大多数模型已预归一化，但请验证）
- 忽略分块重叠（在边界处被分割的句子会丢失上下文）
- 仅存储向量而不存储原始文本（检索时两者都需要）
- 模型更改时不重新嵌入（旧向量不兼容）
- 仅基于准确率选择维度（存储和延迟与维度呈线性关系）

## 调试 embedding

如果搜索结果不佳：

1. 验证查询 embedding 是否非零（空或空白输入会产生零向量）
2. 手动检查已知相关文档的相似度分数
3. 尝试改写查询以匹配文档词汇
4. 检查分块边界，确保相关内容未被跨块分割
5. 跨度量（余弦、点积、欧几里得）比较 top-k 结果以发现归一化问题
6. 使用完全匹配的查询进行测试（从文档中复制一个句子）以确认管道正常工作

## 生产参数

- 分块大小：256-512 tokens
- 分块重叠：50 tokens（分块大小的 10-20%）
- Top-k 检索：直接使用时 5-10，重排序时 50-100
- 相似度阈值：余弦相似度 0.7+（低于此值，结果通常不相关）
- 批量嵌入：每次 API 调用处理 100-500 个文本以提高吞吐量
- 索引重建：当模型更改或文档显著更新时重新嵌入
