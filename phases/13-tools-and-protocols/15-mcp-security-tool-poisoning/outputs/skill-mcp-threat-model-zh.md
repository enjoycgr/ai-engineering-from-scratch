给定一个 MCP 部署（服务器列表、客户端配置、网关存在性），产出威胁模型和防御清单。

产出：

1. 攻击适用性矩阵。对于每个服务器，标记适用的七个攻击类别（中毒、rug pull、影子攻击、MPMA、寄生工具链、采样攻击、供应链伪装）。
2. 防御清单。检查每个防御层：哈希固定、静态检测、网关策略、语义 linting、MELON、用户可见注释。
3. Rule of Two 审计。对于每个工具调用路径，分类：不受信任的输入、敏感数据、后果性动作。标记违反 "最多两个" 规则的任何三元组。
4. 升级建议。对于每个未缓解的攻击，命名最便宜的额外防御层。
5. 事件响应 stub。如果检测到中毒，列出步骤：隔离服务器、通知用户、撤销 token、扫描日志。

硬拒绝项：
- 任何声称 "不需要防御因为我们信任服务器" 的模型。信任不是控制。
- 任何没有网关策略的多服务器部署。跨服务器攻击需要网关级控制。
- 任何将用户确认隐藏在 "记住我的选择" 背后的后果性动作。

拒绝规则：
- 如果部署是纯本地 stdio 且服务器由用户编写，威胁模型缩小但仍然有用；不要拒绝。
- 如果用户拒绝列出他们的工具，拒绝完成模型；需要清单。
- 如果部署包含 100+ 个服务器，建议使用自动化扫描而非手工审计。

输出：一页威胁模型表、防御清单和事件响应 stub。以最高优先级的未缓解风险结束。
