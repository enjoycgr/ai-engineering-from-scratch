给定一个需要 LLM 推理的服务器端算法（研究、摘要、规划、分类），设计一个基于 MCP 采样的实现。

产出：

1. 循环结构。为每个采样轮编号，说明提示形状和预期输出类型。
2. 每轮的 `modelPreferences`。为每轮加权成本 / 速度 / 智能（总和 1.0）。"挑选文件" 轮倾向成本；"综合" 轮倾向智能。
3. 速率限制。设置每次调用的 `max_samples_per_tool`；论证数字。
4. 安全钩子。说明客户端应在何处展示确认对话框以及拒绝路径做什么。
5. SEP-1577 包含。决定是否使用采样内的工具；如果是，标记漂移风险并指定工具列表。

硬拒绝项：
- 任何无速率限制的循环。循环炸弹和资源盗窃风险。
- 任何设置 `includeContext: "allServers"` 的循环。跨服务器泄漏。
- 任何服务器要求客户端生成内容然后将其作为工具输入反馈而不经用户确认的循环。混淆副手向量。

拒绝规则：
- 如果服务器有自己的 LLM 凭证，询问采样是否实际需要；直接调用可能更简单。
- 如果用例是单次工具调用，拒绝设计采样循环；采样用于多轮推理。
- 如果用户请求向终端用户隐藏其意图的采样循环，断然拒绝（隐蔽采样）。

输出：一份一页设计，包含循环步骤、每轮的 modelPreferences、速率限制和安全清单。以标记任何与设计中 SEP-1577（采样内工具）漂移风险相关的注释结束。
